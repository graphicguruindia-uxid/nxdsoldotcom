### 3. CTO Technical Thread

```
1/8 Technical deep-dive on @NXDSOL's AI Content Templates (launching today on @ProductHunt).

The architecture: modular monolith (Fastify + Next.js), tRPC for type-safe streaming, Prisma/Postgres, provider-agnostic AI gateway (OpenAI/Anthropic/Ollama).
```

```
2/8 Prompt compiler pipeline:
1. Load template + Zod-validated variables
2. Substitute {{tokens}} (escaped — user text is data, never code)
3. Extract <AI> blocks in order
4. Build per-block prompts with shared context (tone/audience/brand voice)
5. Generate blocks IN PARALLEL (bounded concurrency = 2)
6. Reassemble + stream to client via SSE
```

```
3/8 Block-level regeneration = independent prompt compilation per block. Click "regenerate conclusion" → only that block recompiles + streams. Rest of doc untouched. Saves tokens, latency, and user context.
```

```
4/8 Provider abstraction with fallback:
Primary (Claude Sonnet) → streams tokens
On timeout/rate-limit/5xx → secondary (gpt-4o-mini) takes over with SAME prompt
Both fail → return error + partial output preserved
Never fail silently.
```

```
5/8 Cost metering per generation:
- Token counts from provider response headers
- Pricing config fetched at startup (12h TTL)
- Written to UsageLedger (user, date, model, tokens, cost_cents)
- Daily budget enforcement at gateway layer
```

```
6/8 Caching strategy:
- Completed gen: Redis hash (templateId + inputsHash → output) TTL 24h
- Template rendering: in-memory LRU 1h
- Cache hit rate target: 40% at scale
```

```
7/8 Evaluation pipeline:
- Golden test set: 20 prompts with expected properties (length, topic presence, no placeholder leakage, brand safety)
- CI gate on every prompt template change
- Prod sampling: 2% scored by LLM-as-judge (relevance, tone match)
```

```
8/8 Shared infra with our 2nd product (Digital Business Planner):
Auth, Workspace, UsageLedger, AI gateway, Monorepo, CI/CD, Monitoring.

Two products, one foundation. 🏗️

Try it: [link]
```

### 5. FAQ Comments (Pre-written, Post as Replies)

| Question | Answer |
|----------|--------|
| "How is this different from Jasper/Copy.ai?" | Those are chat-first. We're template-first: proven structures (hooks, CTAs, limits) + your variables. You're not prompting; you're filling a form that already knows what good looks like. Block regeneration means you fix one section, not the whole thing. |
| "Can I create my own templates?" | Not in v1 (curated library only). Phase 2 (post-launch): invite-only creator program → community marketplace with 70/30 rev share. Sign up for updates in-app. |

| "Do you train on my content?" | No. Your variables + outputs stay in your workspace. We don't train on user data. (Legal review complete.) |
| "Is there an API?" | REST public API for template gallery (read-only). tRPC authenticated API for generation — Pro/Team only. Docs at launch. |
